## Context

用户最新确认的图标是一个 1024 × 1024 的绿色圆角方形，中央为米白色大六边形环，环内是同心、同方向的绿色小六边形镂空。该 PNG 是视觉事实来源，不再使用上一版叶子稿或人工重绘的叶片几何。

项目使用 `AppIcon` asset catalog 作为应用图标，并使用独立的 `menubar-icon` 模板资源作为菜单栏图标。Xcode 工程已指向 `AppIcon`，无需修改构建设置或 Swift 代码。

## Goals / Non-Goals

**Goals:**

- 保持用户确认稿的绿色背景、米白色六边形环和同心小六边形镂空结构。
- 生成现有映射所需的 16、32、64、128、256、512、1024 像素 App Icon PNG。
- 让 App Icon 四角在所有尺寸都具有真正透明的 alpha 通道。
- 生成 18 × 18 和 36 × 36 的黑色六边形环菜单栏模板 PNG，并保证小尺寸下仍然清晰。
- 保持 asset catalog 自包含，并通过资源校验和 Debug 构建。

**Non-Goals:**

- 不保留或恢复叶子主体，不重新引入字母、曲线或装饰纹理。
- 不改变应用行为、Swift 代码、构建设置或依赖。
- 不新增 App Icon set，也不切换到其他资源命名。

## Decisions

1. **使用用户最新确认的 PNG 作为 App Icon 基准。**

   直接使用用户确认的 1024 × 1024 PNG 生成所有 App Icon 尺寸，保留六边形的比例、内外同心关系和背景形状。

2. **保留同心六边形的结构差异。**

   外层使用米白色大六边形环，内部镂空为同心、同方向的小六边形；不通过改变颜色或叠加随机图案增加层次。

3. **使用明确的圆角透明裁切。**

   保留圆角方形背景，圆角外的区域必须是 alpha 0，并在每个输出尺寸验证四角透明，而不是使用黑色或近似背景色填充。

4. **保持现有资源目录映射。**

   不修改 `Contents.json` 的文件名和 1x/2x 映射，仅替换对应 PNG 文件。

5. **菜单栏图标使用独立的黑色模板六边形环。**

   从确认稿的同心结构生成黑色外六边形环和透明内六边形，放大有效绘制区域以适配 18px 菜单栏画布，并保持 `template-rendering-intent` 为 `template`。

6. **验证后再启动应用。**

   检查尺寸、alpha 和透明角，验证 asset catalog JSON，执行 Debug 构建，关闭旧实例并启动最新构建进行视觉检查。

## Risks / Trade-offs

- [小尺寸镂空消失] → 控制菜单栏内外六边形环的厚度，显式检查 18px 和 36px 输出。
- [边缘缩放产生半透明像素] → 从确认稿统一缩放，并检查四角 alpha 为零。
- [背景外区域出现方形底色] → 生成前保留圆角裁切，构建前再次检查所有尺寸。

## Migration Plan

1. 以用户确认稿替换 App Icon PNG 尺寸。
2. 生成黑色同心六边形环菜单栏模板 PNG。
3. 校验资源尺寸、alpha、JSON 和 Debug 构建结果。
4. 如果视觉结果不符合确认稿，仅回退本次资源文件，不涉及应用代码或持久化数据。
