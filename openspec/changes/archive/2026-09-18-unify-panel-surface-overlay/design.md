## Context

当前主面板在 macOS 26 及以上使用 `NSGlassEffectView(.regular)`。`MenuMaterialView` 已有一层位于系统玻璃之上的 AppKit 视图，但亮色使用白色提亮，暗色将该层 alpha 设为 0。详见 proposal.md 和 delta spec。

## Goals / Non-Goals

**Goals:**

- 让亮暗主题使用同一个表面叠加层级。
- 保持亮色当前的白色叠加结果，不调整到 `0.30`。
- 为 macOS 26 及以上暗色玻璃增加 `0.20` 的中性深色低 alpha 补偿，收住 macOS 27 的透底效果。
- 亮色内容卡片使用纯白 `0.20` 低 alpha 叠加，暗色内容卡片和边框保持现有样式。
- 保持系统玻璃、SwiftUI 内容透明和窗口几何不变。
- 清理流程进入非 `idle` 状态后保持面板常驻，直到用户主动回到空闲状态。

**Non-Goals:**

- 不替换 `NSGlassEffectView` 或调整 `NSVisualEffectView(.menu)` 的材质选择。
- 不改变亮色主面板现有的 `0.45 × 0.65` 白色叠加计算。
- 不调整暗色内容卡片、按钮、边框、布局或清理流程。
- 不为系统玻璃增加不存在的固定 opacity 设定。

## Decisions

### 统一叠加视图的生命周期与层级

将现有白色提亮视图抽象为表面叠加视图，在系统材质创建后加入，在 HostingView 加入前保持其 z-order。这样亮暗主题共享同一层级，SwiftUI 内容仍然位于叠加层之上，命中测试和内容布局不变。

### 使用主题化颜色与 alpha，而不是统一数值

亮色继续使用现有白色叠加逻辑，当前默认最终 alpha 为 `0.45 × 0.65 = 0.2925`。暗色使用中性深色叠加，alpha 为 `0.20`。两种颜色不能共用同一个视觉数值：白色用于提亮，深色用于收住透底；统一的是叠加层机制，而不是颜色令牌或亮度结果。

暗色补偿只作用于 macOS 26 及以上的 Liquid Glass 路径，因为本次问题来自 macOS 27 的系统玻璃变化；更早系统继续保持原有 `.menu` 行为，避免扩大兼容性范围。

### 亮色卡片使用轻量纯白叠加

亮色卡片从固定的 `#F7F7F7 @ 0.5` 改为 `Color.white @ 0.20`。纯白低 alpha 在视觉上仍能抬高卡片，但减少固定中性灰对根面板桌面色彩和模糊透出的覆盖；不重新叠加 `thinMaterial`，避免增加第二个取景层。

### 保留显式的主题切换刷新

表面叠加层仍在 `viewDidChangeEffectiveAppearance()` 中更新。主题切换时重新计算颜色和 alpha，跟随系统模式、手动亮色和手动暗色都能得到一致的层级关系。

### 按应用状态控制面板常驻

面板外部点击是否关闭由 `appState` 控制。只有 `idle` 状态允许关闭，`scanning`、`awaitingConfirmation`、`applying`、`completed` 和 `partial` 都保持面板常驻，保证一次清理流程中的扫描、确认、执行和结果界面行为一致。

### Alternatives considered

- **直接设置 `NSGlassEffectView` opacity**：公开 API 没有独立的玻璃 opacity 控制，无法得到稳定的跨系统结果。
- **使用 `tintColor` 代替叠加视图**：由系统决定 tint 的实际混合方式，难以保持亮色现有结果并精确标定暗色补偿。
- **暗色继续不叠加**：无法形成与亮色相同的应用侧补偿机制，也无法轻微收住 macOS 27 的透底变化。
- **把暗色卡片的 0.06 令牌直接复用到主面板**：卡片使用白色提亮，主面板需要中性深色收底，语义和颜色方向不同，不能复用。

## Risks / Trade-offs

- [Risk] 暗色 0.20 的深色叠加在不同桌面背景或显示器上可能显得偏重 → [Mitigation] 仅作用于 macOS 26+，保留单独令牌，后续可在独立 change 中基于截屏调校。
- [Risk] 系统玻璃实现未来继续变化，固定叠加层无法完全锁定透明度 → [Mitigation] 继续把系统玻璃作为主材质，只用低 alpha 层做轻量视觉补偿。
