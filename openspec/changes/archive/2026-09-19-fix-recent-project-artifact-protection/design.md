# Design

## Context

统一扫描按缓存清理 → 项目清理 → 应用残留 → 空间分析顺序执行，前三类的实际候选路径与完整聚合的子树已被所有权屏蔽和 metrics 复用覆盖。缺口出现在项目清理的"近期保护"分支：产物目录名称与项目标记均命中、但项目 30 天内仍在修改时不生成候选也不注册 metrics，空间分析按兜底条款照常进入该子树并逐文件产生候选，绕过了在用保护。

## Goals / Non-Goals

**Goals:**

- 近期保护的产物目录整树不出现在空间分析候选中。
- 该子树的空间统计不受影响。
- 兜底语义收窄后仍覆盖"归属不明确"与"读取失败"两类场景。

**Non-Goals:**

- 不改动缓存侧（策略根恒为候选已屏蔽；临时目录位于 `/private` 保护域，空间分析不可达，无同类漏洞）。
- 策略外缓存域（`~/Library/Caches` 非策略目录）是否整域屏蔽空间分析候选，留待后续单独优化。
- 不改项目清理的 30 天规则、名称表与标记表。

## Decisions

### 1. 受保护子树登记进统一扫描上下文

`scanDeveloper` 在"名称 + 标记命中、近期保护"分支将产物目录登记为受保护子树（`UnifiedScanContext` 新增保护路径集合，按前缀匹配）。空间分析在文件与 metrics 复用两条候选生成路径上，将"受保护子树"与"前序候选所有权"同样视为屏蔽条件，但遍历与字节统计照常进行。

备选方案是给近期项目也生成一个 protected 风险候选：会污染项目清理的候选计数与展示，且 protected 候选在别处有独立语义，不采用。

### 2. 兜底条款移除"近期修改"

规范中的兜底枚举从"近期修改、归属不明确或读取失败"收窄为"归属不明确或读取失败"。近期保护是刻意决策而非信息缺失，不应被后续 provider 推翻；归属不明确与读取失败仍允许空间分析基于自身规则发现文件。

### 3. 保护范围以标记命中为前提

只有同时命中名称与项目标记的目录才登记保护；无标记的通用名目录（如 `Documents/素材/build`）不是项目产物，维持普通目录候选评估，与项目产物标记闸门语义一致。

### 4. VCS 数据目录在候选资格层整树排除

`.git`、`.svn`、`.hg` 的对象文件（pack、loose object）删除会不可恢复地损坏仓库，任何单个文件都不具备"用户可决定删除"的语义。判定放在空间分析候选资格检查（文件与观察复用两条路径共用）：路径任一组件命中即不生成候选。磁盘镜像 bundle 目录（`.vmwarevm`、`.pvm`、`.sparsebundle`、`.disk` 后缀组件）与 VCS 同域：内部成员文件（含被特殊文件规则命中的 dmg/zip）单删即损坏虚拟机，走同一候选资格判定。遍历语义见决策 7（整树跳过）。

### 5. Music 默认资料库路径修正

媒体保护表的 Music 条目原为 `~/Music/Music Library.musiclibrary`，而 Music.app 默认资料库实际位于 `~/Music/Music/Music Library.musiclibrary`（本机实测），少一层导致真实资料库未被排除（遍历触发 TCC 媒体库授权风险）。补齐默认路径，保留原条目兼容用户自定义位置。

### 6. DerivedData 为无歧义产物名，免标记校验

`DerivedData` 只可能是 Xcode 构建产物目录，不存在通用用户以该名称存放个人数据的风险，加入产物目录名单并豁免标记要求：近期项目下走受保护子树通道（空间分析不再逐文件挑 `ModuleCache` 内 `.pcm`），30 天未动则整目录进项目清理候选。`build`/`dist`/`target` 等通用词维持标记要求不变。

### 7. 屏蔽子树整树跳过遍历，体积以差额承接

评审确认 `volumeSummary` 无任何 UI 消费方（仅 ViewModel 持有，Views 零引用）后，"为统计而遍历"的屏蔽子树失去存在意义。近期保护产物与机器管理 bundle（VCS/磁盘镜像）目录在空间分析中整树跳过（不枚举、不计字节），本机实测节省约 14.8 万文件 stat/次扫描。边界：前三类候选覆盖路径语义不变——有完整 metrics 仍复用计字节，无 metrics 仍补扫（读取失败兜底与诊断保留）；决策 4 早先"不跳过遍历"的备选随本决策反转。被跳过与受保护体积通过 `VolumeAnalysisSummary.gapBytes = 总容量 − 可用 − 实测` 在数据层承接，不新增界面。

`/usr/local` 边界统一：`usr` 首组件不再整体保护，改为进入枚举并仅保护除 `local` 外的二级子项，使第三方软件区与 `/opt` 一致纳入统计（两者均不产候选，仅统计口径对齐）。

## Risks / Trade-offs

- [Risk] 单独调用空间分析（无统一扫描上下文）时没有保护登记，近期项目内大文件仍会出现 → 与既有"单独调用无前序候选上下文"语义一致，产品入口统一扫描不受影响。
- [Risk] 用户确实想单独清理某个在用项目的 `node_modules` → 项目保持 30 天不动即自然进入项目清理候选，路径存在而非绕道。
- [Risk] 跳过遍历后 `measuredBytes` 缺口增大 → `gapBytes` 差额字段承接；未来概览 UI 以差额呈现"系统与其他"，不回填逐文件测量。

## Migration Plan

无需数据迁移；下一次统一扫描生效。
