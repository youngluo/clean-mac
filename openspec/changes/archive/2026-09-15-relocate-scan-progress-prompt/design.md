## Context

当前 `CleaningView` 在圆形主按钮下方直接放置 provider 面板。面板内部同时包含“扫描进度”标题和当前 provider 的动态说明；扫描开始时 provider 状态尚未到达，还会短暂显示“准备统一扫描”。空闲态的 `IdleView` 已在圆形按钮下方使用一行安全扫描辅助说明。

扫描阶段文案已经由现有进度事件按当前 locale 解析，视图可以直接复用这一数据，不需要修改扫描服务或状态模型。

## Goals / Non-Goals

**Goals:**

- 让扫描阶段提示固定出现在圆形主按钮下方，并且始终保持单行。
- 让扫描提示与空闲态初始辅助提示复用相同的字体、颜色、内边距和垂直间距，只更新描述文案。
- 让扫描态提示与 provider 面板的间距等于空闲态提示与授权提示面板的间距。
- 扫描准备阶段也提供提示，不在 provider 面板中重复显示文本。
- provider 面板在所有工作状态和结果状态下仅保留四个分类状态行，不显示阶段标题。
- 保持空闲辅助说明、provider 状态数据、取消操作和候选列表行为不变。

**Non-Goals:**

- 不改变扫描顺序、进度事件、候选数据或清理状态机。
- 不新增本地化 key，不调整空闲态文案和圆形按钮文案。
- 不改动候选列表、权限提示或面板整体尺寸策略。

## Decisions

### 1. 复用空闲态提示元素

将空闲态圆形按钮下方的辅助文案提取为共享的单行提示元素。清理视图在扫描中使用同一个元素，只替换描述文本；圆形按钮与提示之间沿用空闲态的 `heroSection` 间距和提示自身的顶部光学修正，提示与 provider 面板之间也使用同一段 `heroSection` 间距。非扫描状态不挂载提示内容，并保留原有的圆球底部缓冲，避免完成态留下多余的阶段文案空间。

备选方案是在 provider 面板上方复制一份提示，或让 `IdleView` 跨状态持有提示，但前者仍会重复信息，后者会破坏当前由 `MenuBarView` 分发的视图边界，因此不采用。

### 2. 复用扫描进度数据并为准备阶段提供回退文案

提示文案优先取当前扫描 provider 的进度阶段；如果扫描已经开始但 provider 状态尚未到达，则显示现有“准备统一扫描”本地化文案。provider 切换时由既有 `scanProgress` 更新文本，不增加新的 ViewModel 状态。

### 3. 单行只显示描述文案

提示元素直接展示解析后的扫描描述，不显示 provider 分类名称。文本限制为一行，超长文案使用末尾省略，保持与空闲态相同的字号、颜色和布局，不额外引入跑马灯或独立动画。

备选方案是继续使用带几何测量和状态的跑马灯组件，虽然可以展示完整长文案，但会使扫描提示不再是空闲态的同一视觉元素，增加不必要的布局差异，因此不采用。

### 4. 扫描中的 provider 面板只保留状态行

扫描时隐藏面板标题和动态说明；没有 provider 状态时不再渲染“准备统一扫描”回退面板，让新的圆球下方提示承担准备阶段反馈。进入等待确认、清理或结果状态后，面板仍只保留四个分类状态行，不恢复任何阶段标题或扫描说明行。

### 5. 保持现有本地化边界和辅助功能

所有显示文案继续通过 `@Environment(\.locale)` 和现有 `L10n` 解析。提示组件不承载交互，扫描状态仍由 provider 行图标、圆形按钮和取消按钮表达；减少动态效果时不启动滚动动画。

## Risks / Trade-offs

- **[扫描刚开始时 provider 状态可能尚未建立]** → 使用现有“准备统一扫描”文案作为提示槽回退，并移除 provider 面板中的空状态提示。
- **[长文案在单行提示中被截断]** → 统一使用末尾省略，保留当前扫描阶段的前部描述；扫描详情仍通过 provider 状态行和实时计数表达。
- **[移除 provider 标题会减少阶段语义]** → 四个 provider 行仍保留分类名称、状态图标和实时计数，状态信息不依赖额外标题。

## Migration Plan

1. 更新清理交互 delta spec 和任务清单。
2. 调整 `CleaningView` 的圆球、提示槽和 provider 面板结构，复用已有进度数据与本地化文案。
3. 执行 OpenSpec 严格校验、`git diff --check` 和 Debug 构建。
4. 关闭旧的 Spotless 实例并启动最新构建；如需回滚，恢复 `CleaningView` 中原 provider 标题和说明布局即可。
