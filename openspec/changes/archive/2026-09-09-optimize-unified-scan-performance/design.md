## Current Flow

```text
缓存扫描 ─────┐
项目扫描 ─────┼─> 各自读取目录和文件属性
残留扫描 ────┘
                     │
                     ▼
空间分析从启动磁盘重新遍历
```

空间分析负责启动磁盘统计和未归属文件候选。它不能简单排除所有已经扫描过的目录，因为第一次扫描可能只完成目录发现，或者空间分析仍需要识别目录内部的安装包、压缩包和大文件。

## Decision 1: One directory aggregation result

将目录聚合结果定义为一次遍历产生的结构，至少包含：

- 实际分配空间，用于所有界面和清理汇总；
- 逻辑文件大小，用于阈值判断和清理前复核；
- 硬链接去重后的文件数量；
- 扫描是否完整；
- 首次遍历中发现的空间分析候选观察项。

缓存、项目和残留候选直接使用同一结果，不再由 `appendExisting` 为目录重新计算逻辑大小。

## Decision 2: Per-run scan context

`scanUnified` 创建本次扫描独有的上下文，按规范化路径记录完整扫描的目录边界和聚合结果。上下文只在本次扫描中存在，不做持久化索引。

只有以下目录才可以登记为可复用边界：

- 目录聚合正常完成；
- 没有因为取消、超时、权限错误或入口数量限制而提前结束；
- 已完成该目录内后续规则需要的文件属性读取。

空间分析遇到已登记边界时，将其实际占用空间合并到对应的启动磁盘统计，并消费上下文中已收集的候选观察项；未登记目录继续使用全局遍历。

## Decision 3: Ownership and completeness

目录所有权按最具体的已登记边界生效。父目录候选已经覆盖其子树时，不再为同一子树生成重复的空间分析文件候选；父目录候选本身仍保持待复核状态。

为了保持全面性，空间分析规则在首次聚合该目录时执行：

- 安装包和压缩包按全局规则识别；
- `~/Downloads`、`~/Desktop`、`~/Documents` 中超过 10 MB 的普通文件按空间分析规则识别；
- 保护目录、`Library` 候选边界、符号链接和不在启动卷上的路径继续遵循现有安全规则。

空间分析观察项只在聚合目录本身可能产生空间分析候选时收集。缓存和应用残留入口位于 `Library` 下，空间分析会排除这些路径，因此只计算它们的实际占用、逻辑大小和硬链接去重信息，不读取候选观察所需的修改时间，也不逐文件执行空间分析规则。项目产物位于用户可分析目录时继续收集观察项。

临时目录不执行 `lsof` 或其它逐文件占用检查。扫描阶段只依据文件类型、修改时间、所有者和符号链接状态筛选候选；用户确认清理后重新校验路径、文件身份、实际大小和逻辑大小，文件在扫描后发生变化时跳过。这样不会因为外部进程检查阻塞扫描。

临时目录候选只包含当前用户拥有、超过 15 天未修改的普通文件，因此使用系统废纸篓 API 直接移动，不再为这些文件调用管理员特权命令。系统缓存和旧日志仍按原有 7 天规则处理，Time Machine 操作仍按原规则使用管理员授权。

如果目录聚合不完整，空间分析不得复用该结果，必须尝试补扫，并将状态标记为部分完成或不可用。

## Decision 4: Keep the global fallback

空间分析仍保留一次启动磁盘全局遍历，负责未被其他 provider 完整覆盖的目录。该遍历只负责兜底，不改变现有安装包、压缩包、普通大文件和 Time Machine 的候选规则。

暂不并行执行多个 provider。先消除重复 I/O，再通过阶段耗时、实际读取条目数和复用目录数判断是否需要有限并发。

## Decision 5: Reuse authorization within one cleanup session

需要管理员权限的候选项仍在一次命令中批量执行，但授权上下文不再只绑定到单次 `execute` 调用。`CleanerService` 持有一个仅存在于当前清理会话的授权上下文：首次执行前通过 macOS Authorization Services 请求 `system.privilege.admin`，并将同一个 `AuthorizationRef` 直接传给特权命令执行入口；后续重试继续使用同一引用，不再启动依赖独立授权上下文的 `osascript`。

会话在开始新的统一扫描、用户点击“完成”或取消清理、以及服务释放时释放授权。应用不读取或持久化密码，也不安装常驻特权 helper。授权取消时不建立会话；如果系统撤销或失效授权，当前操作按现有失败结果处理，不自动循环弹窗。

## Decision 6: Refresh disk access at two existing lifecycle points

完全磁盘访问状态只在两个现有入口刷新：应用重新激活时，以及面板重新打开时。刷新是只读探测，不自动打开系统设置、不自动请求权限，也不改变扫描候选规则。

## Verification

- 增加测试验证目录实际大小和逻辑大小只计算一次并都能传递到候选项。
- 增加测试验证已扫描目录不会被空间分析重复递归，同时未归属目录仍能发现候选。
- 增加测试验证不完整目录不会被错误标记为可复用。
- 执行 `git diff --check`、Debug 构建和可运行的测试编译；完整 XCTest 若仍受测试运行器环境影响，单独记录该限制。
- 验证一次清理会话中的多次特权清理复用授权上下文，并在会话结束后释放上下文。
- 验证应用重新激活和面板重新打开都会刷新完全磁盘访问状态。
