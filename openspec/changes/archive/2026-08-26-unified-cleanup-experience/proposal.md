## Why

CleanMac 当前把一键清理、大文件扫描和开发清理拆成多个入口，用户需要判断进入哪个流程，且一键清理不会统一检查启动磁盘、应用残留、安装包和项目依赖。现在需要将所有检查收敛到一个主界面，在保持安全边界的同时让用户通过一次点击获得完整进度和结果。

## What Changes

- **BREAKING** 将多个清理入口合并为单一主界面和唯一的“一键清理”入口。
- 在同一界面内展示统一扫描、待确认项目、确认操作和最终结果，不再单独进入大文件扫描页面。
- 扫描完成后继续留在主界面，圆形主操作显示“扫描完成”并停止呼吸动效，provider 日志下方直接展示候选结果和确认操作。
- 统一扫描深度清理、已卸载应用残留、缓存与服务、项目构建产物，以及合并后的大文件扫描（安装包、启动磁盘文件和目录、Time Machine）。
- 扫描阶段只读取和计算，不执行任何删除；所有可删除项目都必须经过用户最终确认。
- 安全项目可以默认勾选，应用、残留、大文件扫描候选和项目依赖默认不勾选。
- 最终确认后，所有文件和目录统一进入 macOS 废纸篓，并在“可清理项目”中直接更新逐项状态，不再展示独立的清理结果汇总。
- 扫描完成后的 provider 分类列表标注“已扫描完成”，便于区分扫描结果和清理操作。
- 扫描中的 provider 按分类实时显示实际检查过的文件数，扫描完成后再显示发现的候选项目数和可测量体积，避免混淆两种统计口径。
- 扫描进度按时间节流，统一扫描完成时一次性提交候选集合，减少事件积压和主线程重复刷新，同时保留完整扫描范围。
- 将 npm、pnpm、pip、Homebrew、Xcode 等全局开发工具缓存统一归入“缓存清理”并默认不选中；项目清理只处理配置项目根目录内超过 30 天未更新的可重建产物。
- 扩展高置信应用残留目录并在 Bundle ID 比对前归一化 `.plist` 和 `.savedState` 后缀；安装包补充 XIP 和 IPSW。
- 在 README 中记录各分类的具体路径、默认选择、安全边界和暂不扫描的通用临时目录。
- provider 和可清理项目分组统一使用“缓存清理”“项目清理”“应用残留”“空间分析”，扫描中保留说明行，扫描完成后通过短动画收拢间距；有对应候选分组时，上方 provider 行可点击定位到该分组。
- 圆形主按钮与 provider 进度面板之间不再显示额外的阶段辅助行，扫描和清理状态统一由圆形按钮及 provider 区域表达。
- 大文件扫描分类在有候选但无法测量体积时显示“大小未知”，不隐藏大小字段。
- 候选项在上侧展示名称和体积，在下侧展示支持末尾省略的完整路径；移除与取消操作在底部并列展示。
- 候选分组与顶部内容保持一致的水平边距，可滚动候选区域高度限制为 320 至 640。
- 候选项使用更紧凑的圆形复选框，减少列表中的控件占用。
- 项目清理仅列出超过 30 天未更新且当前未使用的项目产物和 `node_modules`，不要求 `package.json` 或 lock 文件；允许计算整体体积，但不展示内部文件，不设置大小阈值。
- 优化全盘遍历的元数据读取和取消检查，减少重复属性访问，但不缩小启动磁盘扫描范围或改变隐私排除边界。
- 将磁盘访问提示改为简短、柔和且单行可读的授权文案。
- 将权限提示右侧操作整理为统一高度、紧凑间距的操作组，避免按钮与说明文字互相挤压。
- “去设置”操作仅保留文字，避免图标造成视觉噪音。
- 统一所有可用的界面操作使用手形指针，禁用操作保持默认指针。
- 为圆形“一键清理”使用 macOS 系统蓝，并保留克制的白色悬停边缘和按下回弹。
- 移除圆形主按钮图标，仅通过阶段文案和整个圆形按钮的轻微运动表达工作状态。
- 扫描和清理进行中不显示额外 loading，改为让整个圆形主按钮做轻微呼吸、抬升和倾斜运动。
- 将主操作设计为圆形“一键清理”按钮，并使用“一键清理”“正在扫描”“扫描完成”“正在清理”“清理完成”五种阶段文案。
- 统一权限、部分扫描、失败、跳过、确认取消和待确认项目的结果展示。

## Impact

- 修改 `CleanerViewModel`、清理模型、扫描/执行服务和 SwiftUI 主界面状态流。
- 增加应用本体及残留、安装包、缓存服务和项目依赖候选的扫描与安全策略。
- 保留现有废纸篓路由、权限限制、照片图库排除、启动磁盘边界和 Time Machine 安全确认。
- 扩展服务、视图模型和 UI 测试，并执行 Debug 构建和运行验证。
