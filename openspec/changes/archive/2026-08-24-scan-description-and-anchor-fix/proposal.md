## Why

扫描时每个 provider 行都预留说明位置，列表显得松散；同时候选分组通过中文 `source` 文案推断类型，旧文案残留会让应用残留和空间分析的点击锚点失效。需要把扫描说明和候选分组身份统一起来。

## What Changes

- 将当前正在扫描分类的说明统一显示在“扫描进度”面板标题下方的单行说明区域，文案以“正在”开头，超出宽度时循环滚动并在分类切换时平滑替换。
- 调整扫描进度面板的标题、说明和 provider 行间距，保持信息紧凑但不拥挤。
- 移除 provider 行末尾与左侧状态图标重复的状态文字，保留数量和大小信息。
- 扫描过程中实时更新当前 provider 已发现的项目数量，完成后再写入最终统计。
- 修复四类 provider 分组的滚动锚点，使用一次性布局和稳定的目标 ID，确保应用残留、空间分析与其他分组一致跳转。
- 防止扫描列表尚未挂载时提前消费跳转目标，并在候选列表挂载后补执行待处理跳转。
- 移除 provider 行下方各自的说明占位，扫描完成后不增加额外行高。
- 让四类候选直接携带对应的 provider 身份，按 provider 分组并使用同一身份完成顶部点击和候选锚点定位。
- 停止使用中文显示文案作为分组映射键，统一使用“缓存清理”“项目清理”“应用残留”“空间分析”四类名称。
- 保留候选来源文案用于具体项目识别，但不让来源文案参与分组、点击状态或锚点定位。
