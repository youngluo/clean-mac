## MODIFIED Requirements

### Requirement: 固定的主清理界面

应用 SHALL 在稳定的弹出面板中统一呈现标题、启动磁盘摘要、圆形主操作、进度状态和结果内容，不应再提供独立的空间分析、开发清理、复核或完成页面。扫描和清理状态 SHALL 由圆形主操作与 provider 区域表达，圆形主操作和 provider 区域之间不得插入重复的阶段辅助行。

#### Scenario: 从主界面开始

- **WHEN** 用户点击“一键清理”
- **THEN** 同一界面的圆形主操作变为“正在扫描”
- **AND** 当前 provider 和进度直接显示在圆形操作下方
- **AND** “扫描进度”标题下方的单行说明区域显示当前正在扫描 provider 的范围说明
- **AND** 范围说明文案以“正在”开头
- **AND** 说明超出可用宽度时循环滚动，provider 切换不会改变界面布局
- **AND** 扫描进度标题、说明和 provider 行之间保持一致的垂直间距
- **AND** provider 行左侧图标表达状态，右侧不重复显示状态文字
- **AND** 当前进行中的 provider 行实时显示已发现的项目数量

#### Scenario: 扫描说明切换

- **WHEN** 当前正在扫描的 provider 发生切换
- **THEN** “扫描进度”标题下方只显示新 provider 的单行范围说明
- **AND** 新范围说明文案以“正在”开头
- **AND** provider 行本身不再显示各自的说明行
- **AND** 说明文字切换不改变说明区域高度，不产生额外的垂直跳动
- **AND** 当前 provider 的项目数量随扫描发现结果递增

#### Scenario: 检查完成后继续在主界面确认

- **WHEN** 统一扫描完成
- **THEN** 圆形主操作显示“扫描完成”并停止工作动效
- **AND** provider 分类列表显示“已扫描完成”标题
- **AND** 扫描说明区域收起且不在圆形操作与 provider 区域之间新增提示行
- **AND** provider 日志和候选结果按顺序保留在同一主界面中
- **AND** provider 与可清理项目使用“缓存清理”“项目清理”“应用残留”“空间分析”四类名称
- **AND** 有对应候选分组的 provider 行可点击并定位到对应分组，没有对应分组的 provider 行不可点击
- **AND** provider 点击始终定位到匹配的候选分组，不受候选来源展示文案变化影响
- **AND** “应用残留”和“空间分析”与其他 provider 使用相同的稳定锚点规则
- **AND** 候选复核列表尚未显示时 provider 行不可点击，列表显示后待处理目标仍能正确跳转

#### Scenario: 从主界面取消

- **WHEN** 用户在扫描或清理过程中点击“取消”
- **THEN** 当前任务在安全范围内停止启动新的操作
- **AND** 界面恢复为空闲状态的“一键清理”
