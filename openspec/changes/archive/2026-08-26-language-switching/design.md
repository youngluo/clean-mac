## Context

CleanMac 目前由 AppKit 的 `AppDelegate` 手动创建菜单，由 SwiftUI 展示主界面，用户可见文案分布在视图、模型、ViewModel 和扫描服务中。应用已有主题偏好和根视图重建机制，但没有 String Catalog 或应用级语言状态。

## Goals / Non-Goals

**Goals:**

- 在现有右键菜单中提供跟随系统、简体中文和 English。
- 让菜单、主界面、扫描进度、候选状态和应用生成的诊断使用同一语言。
- 持久化语言偏好，并在空闲状态切换后立即更新界面。
- 让扫描会话中的文本保持语言一致，不改变候选数据和文件系统状态。
- 让扫描和清理线程不依赖全局语言状态，不在业务层生成已经解析的界面字符串。

**Non-Goals:**

- 不翻译文件名、文件路径、Bundle ID 或无法分类的外部命令原始错误；可识别的文件操作权限错误使用应用当前语言显示。
- 不在本次变更中增加语言包下载、在线翻译或用户自定义翻译。
- 不改变现有主题行为、扫描范围和清理策略。

## Decisions

### 1. 使用应用级语言状态

新增 `AppLanguage` 枚举和语言状态控制器，保存 `system`、`zh-Hans`、`en` 三种值。控制器使用独立的 UserDefaults key，启动时恢复偏好；跟随系统使用系统首选语言，非支持语言回退到简体中文。控制器是应用内唯一的语言状态来源，UserDefaults 只由控制器读写。

AppDelegate 持有控制器并将其传入 SwiftUI 根视图；`MenuBarView` 观察控制器的发布状态并注入对应 locale，AppKit 菜单也从同一控制器读取 locale。语言选择后当前已打开的界面也会立即刷新。主题偏好继续由现有独立状态维护。业务层不得直接读取 UserDefaults 或通过隐式全局状态解析语言。

### 2. 采用 String Catalog 和语义化 key，保留运行时 locale

新增应用资源 String Catalog，提供 zh-Hans 和 en 翻译。固定文案统一使用按界面职责命名的语义化 key，由统一的本地化解析器集中解析；SwiftUI 视图通过环境 locale 显示。

Service、ViewModel 和跨任务事件使用 `LocalizedMessage` 保存本地化 key、参数或原始文本，只有展示边界才将消息解析为当前 locale 的字符串。这样同一份扫描结果可以在语言切换后重新渲染，扫描线程也不需要重复访问 Bundle。

候选项的路径、显示名称、Bundle ID、用户文件名和无法分类的命令输出属于外部数据，作为原文保留。文件操作返回的已知权限错误按错误码和常见系统描述识别，并使用当前语言的 CleanMac 文案；其余系统错误保留原始信息。

数量、体积和失败前缀使用带参数的本地化格式，不通过多个已翻译片段拼接。体积格式化必须显式使用当前应用 locale。

### 3. 将语言切换限制在空闲状态

右键菜单保留“主题”菜单，并在其后增加“语言”子菜单。扫描、清理和结果展示期间禁用语言菜单；空闲时语言切换只更新偏好和视图，不触发扫描、不清理文件、不重置 ViewModel 数据。

这样可以避免已生成的候选、诊断和结果文本与新语言混排，也避免切换语言时取消正在运行的文件操作。用户完成当前会话并回到空闲状态后即可切换语言。

### 4. 保持菜单与 SwiftUI 的本地化边界清晰

AppKit 菜单标题由语言状态控制器解析，菜单选项使用状态标记表示当前值；SwiftUI 根视图使用 environment locale。语言子菜单的标签、主题名称和退出项均纳入本地化资源，“跟随系统”随当前界面语言显示，“简体中文”和“English”保留各自的原生名称，技术名称和外部数据保留原文。

### 5. 延迟解析业务消息

应用生成的扫描阶段、诊断、候选保护原因、清理结果和 provider 状态消息统一使用 `LocalizedMessage`。静态文案使用 key，带动态内容的文案使用明确的消息 case 保存参数，无法分类的外部输出使用 raw 文本。视图通过当前 locale 解析消息；业务模型不再暴露依赖全局 locale 的 `String` 文案。

清理服务只生成消息值和原始文件数据，不在扫描热路径中解析 String Catalog。ViewModel 只转发消息，避免在事件接收时将消息固定为某一种语言。

## Risks / Trade-offs

- **[切换语言不是所有状态都可用]** → 菜单项显示禁用状态，避免中断扫描或造成结果混排；空闲时立即生效。
- **[遗漏本地化文案]** → 对视图、模型、服务和菜单中的用户可见文案建立覆盖清单，并增加关键语言模式测试。
- **[翻译文本长度变化]** → 菜单继续使用系统布局，SwiftUI 文案避免依赖固定文本宽度；必要处使用可伸缩布局。
- **[系统语言不受支持]** → 跟随系统仅选择已支持的英文或简体中文，否则回退到简体中文。

## Migration Plan

1. 添加语言模型、偏好存储和 String Catalog，并接入 AppDelegate 的右键菜单。
2. 将 SwiftUI、模型、ViewModel 和扫描服务中的用户可见固定文案迁移到本地化 key。
3. 将语言 locale 注入根视图，验证空闲状态的即时刷新和重启后的偏好恢复。
4. 验证扫描和清理状态下语言菜单禁用，确认文件操作和候选数据不受影响。
5. 将已解析的业务文案迁移为 `LocalizedMessage`，删除 `L10n.current` 和服务层的语言隐式依赖。
6. 补充格式化、结构化错误、消息重渲染和扫描热路径的测试。
