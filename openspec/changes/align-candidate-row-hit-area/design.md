## Context

`CandidateReviewSection` 使用 `ScrollView` 和分组 `VStack` 展示候选项。当前 `CandidateRowView` 内部有两个独立按钮，行外的 `contentShape` 只能影响命中形状，不能把名称按钮的操作扩展到路径、大小和空白区域。分组标题与候选行虽然复用了水平间距常量，但列表内容没有对每个分组和行声明统一的全宽布局边界。

## Goals / Non-Goals

**Goals:**

- 让可选候选项的整行成为一个可访问、可聚焦的选择控件。
- 让整行按钮的左右边界与所属分组标题的内容区域一致。
- 保留当前选中状态、不可选状态、清理结果展示、右键排除菜单和滚动锚点行为。

**Non-Goals:**

- 不改变候选项模型、选择业务逻辑、清理操作或候选分组规则。
- 不新增视觉背景、分隔线、动画或新的交互入口。

## Decisions

### 1. 用单个整行 Button 承载选择操作

当候选项没有清理结果时，用一个 `Button(action: toggle)` 包住整行内容，并移除选择图标和名称上的嵌套按钮。使用 `.buttonStyle(.plain)` 保留当前视觉表现，用 `.disabled(!candidate.isEligible)` 保持不可选候选项不响应。

使用 `Button` 而不是 `onTapGesture`，因为它能保留 macOS 的键盘焦点和辅助功能语义；使用单一按钮也避免嵌套按钮在点击路由和可访问树中的歧义。清理结果行继续渲染为非交互内容，不把已处理状态误当作可选操作。

### 2. 将行内容显式撑满列表宽度

候选行的内容根视图使用 `.frame(maxWidth: .infinity, alignment: .leading)`，并在命中形状之后保留现有 `LayoutSpacing.small` 水平内边距和 `LayoutSpacing.row` 垂直内边距。`CandidateReviewSection` 的列表内容和每个分组标题也声明相同的全宽布局边界，继续使用现有 `LayoutSpacing.listGutter` 与 `LayoutSpacing.small`，不引入新的硬编码间距。

这样行级按钮覆盖列表内容的完整宽度，而名称、路径、体积和分组标题文字仍保持一致的左右内缩。候选行中的体积信息可以稳定地落在与分组标题汇总信息相同的右侧内容边界附近。

### 3. 保留右键菜单挂载在行级容器

候选行的上下文菜单继续挂载在整行容器上，只在存在 URL 且候选可清理时提供排除操作。左键选择和右键菜单使用不同的系统交互路径，不改变排除回调或本地化文本。

### 4. 保持列表身份与滚动结构不变

不改变现有 `ForEach` 的 `Identifiable` 候选项和 provider 分组标识，也不改变 `ScrollViewReader` 的定位方式。改动仅限于候选行的视图层级和候选列表的宽度约束，避免影响选择状态更新与 provider 跳转。

### 5. 禁用候选行的按下态颜色反馈

为候选行使用局部的 `ButtonStyle`，只返回按钮标签，不根据 `configuration.isPressed` 修改不透明度、前景色或缩放。候选名称显式使用主题正文色，路径和体积继续使用次要文本色；选择图标保留其选中与未选中的主题色变化。

不修改共享的主题按钮样式，避免影响“移到废纸篓”、取消和其他操作按钮的既有反馈。

## Risks / Trade-offs

- [整行按钮可能让用户误触选择] → 候选项本身是选择型清理单元，整行命中是明确需求；不可选和已处理候选仍禁用或不渲染为按钮。
- [按钮标签的宽度提议在 ScrollView 中不稳定] → 同时给列表内容、分组容器、分组标题和候选行设置全宽 frame，并沿用同一组水平间距常量。
- [整行按钮与上下文菜单组合导致右键行为变化] → 保留现有上下文菜单条件和挂载位置，通过 Debug 构建与运行检查左键选择、右键排除和滚动列表表现。
