## Context

目标是让主面板与 App 自身的右键菜单看起来是同一张表面。右键菜单是系统 `NSMenu`，实测：

- 表面 `R244 G246 B247`（比背景亮约 9 个色阶，G、B 比 R 高 2~3，偏冷近白）
- 主文字 `#1B1B1B`（亮度 27），次要文字（快捷键 ⌘Q）`#919192`（亮度 146）
- 分隔线最深处比表面暗约 59 个色阶

面板实测 `R242 G244 B245`，与菜单表面只差 2 个色阶，色相特征一致；主文字近黑、次要文字约 150 亮度，三档角色一一对应。因此差异不在配色表，而在**材质族**：此前为追求白度把根材质从 `.menu` 换成了 `.popover`，白度达标但材质与菜单不同族。

两条限制条件也在排查中确认：

- 白色背景下明暗可调空间极小。面板 242~245、背景 246、纯白 255，天花板只有约 9 个色阶；因此近白背景下不能靠明暗拉层次，只能靠材质本身的色相与边缘处理。
- 内容卡片是独立一层。实测根背景提亮从 0.22 提到 0.45 时，面板表面由 R241 升到 R244，而卡片恒为 `#EFF0F1` 不动——根背景越白，卡片相对越像灰块，必须与根背景共用同一个提亮值。

## Decision

根材质使用 `.menu`，与 App 自身右键菜单同族，`blendingMode = .behindWindow`、`state = .active` 不变。

在其之上保留唯一一层**纯白**低 alpha 提亮视图（`SurfaceLift.whiteAlpha`，默认 `0.45`），把 `.menu` 的底色标定到与右键菜单实测表面一致；提亮只在亮色外观下生效，暗色下 alpha 取 0，避免冲淡暗色表面层级。提亮色用 `NSColor.white` 而非 `windowBackgroundColor`：后者在浅色下约为 `#ECECEC`，本身偏灰，叠加等价于灰蒙版，alpha 越高越闷。

内容卡片同样使用 `thinMaterial` 作为分组依据，并叠加与根背景同源的提亮（共用 `SurfaceLift.whiteAlpha`），使其落在面板表面之上而不是之下；分组改由细描边承担。共用一个值是为了避免根背景与卡片各自漂移后再次出现亮度断层。

边缘处理参考系统菜单：外侧描边在亮色下取 `separatorColor` alpha `0.05`（比系统菜单实测的约 31 个色阶更轻），内侧补一道纯白亮边（`rimInset 1`、`rimWidth 0.5`、`rimAlpha 0.45`），用高光而不是灰线维持近白背景上的轮廓。暗色外观的描边标定与亮色不同，维持 alpha `0.35`。

面板不叠加系统窗口投影（`hasShadow = false`）。系统窗口投影只有开/关、贴边环实测比表面暗 103 个色阶且无公开 API 可调；自绘投影需要窗口留出透明边距并连带改动面板尺寸与定位的四处几何，收益不抵复杂度，因此不采用。

提亮视图与亮边在 z-order 上位于根材质之上、SwiftUI hosting 之下：该顺序由 `MenuMaterialView.init` 先添加材质、提亮层与亮边，`PanelContentViewController.viewDidLoad` 后添加 hosting 视图自然得到，因此不影响命中测试。

## Visual Target

```text
桌面背景
  ↓
.menu 原生毛玻璃（与 App 右键菜单同族，透底 + 模糊）
  ↓
纯白低 alpha 提亮（仅亮色）
  ↓
接近右键菜单表面（R244 G246 B247）的主面板
  ↓
内侧纯白亮边 + 极轻外侧描边
  ↓
透明 SwiftUI 内容；内容卡片共用同一提亮
```

- 面板表面落在 `R244 G246 B247` 附近，与 App 自身右键菜单一致。
- 内容卡片不出现比面板表面更暗的灰块。
- 近白背景下仍能辨认轮廓：靠内侧亮边与极轻外侧描边，不引入灰色填充。
- 暗色外观下不叠加提亮，表面层级保持系统材质原生表现。
- 圆角与主题切换行为保持不变。

## Alternatives Considered

- 继续用 `.popover`：白度更高，但与右键菜单不是同一族材质，整体观感对不上，本轮改回 `.menu`。
- 用 `windowBackgroundColor` 提高覆盖比例：颜色来源本身偏灰，alpha 越高表面越暗，与"更白"方向相反。
- 把 SwiftUI 内容交给 `NSGlassEffectView.contentView` 托管：看似符合该 API 的设计用法，实测会破坏尺寸传递链，表现为面板高度被钉死、状态变化时内容被裁切；改为内容以约束贴在表面上、玻璃只当背景。
- 用 `style = .clear` 换取更浅的边框线：`.clear` 同时显著提高玻璃透明度，使内容卡片的 `thinMaterial` 采样到的底色改变、渲染出发灰的方块，得不偿失，已回退到 `.regular`。
- 换成完全不透明的白色根材质（`contentBackground`/`windowBackground`）：白度最高，但一次性丢掉透色与模糊。
- 只提亮根背景、不管内容卡片：实测卡片读数不随根背景变化，面板变白只会把卡片衬得更灰。
- 替换系统投影为自绘投影：可实现可调强度与扩散，但需窗口留透明边距并连带补偿面板尺寸、定位、边缘钳制与点击判定四处几何，复杂度不划算，最终选择不叠投影。
- 改用 `.withinWindow` 混合：只在窗口内取景、读不到桌面，会改变透底行为。
