## Context

当前主界面由 `MenuBarView`、`IdleView`、`CleaningView` 和候选项组件共同组成。顶部定位使用 `22pt`，工作态内容区使用 `14pt`，圆球工作态还会放大并增加阴影，因此圆球下方需要额外的布局缓冲。多个视图各自直接写入间距数字，且 `CompletedView` 已没有调用方。provider 状态行还会把所有 partial 结果显示为警示图标，即使候选数为 0，也会让空结果看起来像异常。

## Goals / Non-Goals

**Goals:**

- 只增加工作态圆球下方的布局缓冲，不改变圆球顶部定位。
- 用集中、语义化的间距常量替代当前生效视图中的重复间距字面量，保留现有信息密度。
- 删除确认没有引用的旧完成态视图。
- 让 0 项的 provider 状态显示为正常完成态，同时保留有候选项的 partial 状态提示。
- 将圆球呼吸效果限制在扫描阶段，避免清理执行或结果状态继续产生动态干扰。
- 在统一候选入口过滤实际测得为 0 KB 的可清理候选项，避免展示无法释放空间的空文件或空目录；大小未知的候选项继续保留。
- 在候选列表标题中保留已选大小，并追加全部候选项的已知大小总和，使用 `/` 分隔，避免用户只能看到当前选择而无法估算全部可清理空间。
- 仅将候选项名称作为选择按钮，路径、大小和行内空白不触发选择；已完成、受保护或其他不可选候选保持禁用。
- 清理执行状态继续渲染底部操作区，保留“移到废纸篓”按钮并依赖 `isCleaning` 禁用重复点击；“完成”按钮也始终保留，但在清理执行期间禁用，避免触发 `resetToIdle()`。

**Non-Goals:**

- 不调整候选分组间距、候选列表高度或扫描说明收起逻辑。
- 不改变清理行为、候选排序、状态机、圆球尺寸、颜色或动画参数；仅调整呼吸效果的启用状态。
- 不引入新的依赖，也不修改持久化数据。

## Decisions

### 1. 仅在工作态圆球下方增加缓冲

在 `CleaningView` 中只给 `PrimaryActionCircle` 增加底部布局缓冲，使用 `8pt`，保留根 `VStack` 的现有 `14pt` 分段间距。这样圆球顶部和中心位置不变，provider 面板、候选列表以及操作按钮之间的间距也不会被一并放大。

备选方案是修改整个 `CleaningView` 的 `VStack` 间距，但这会同时扩大所有内容区间距，无法精确解决圆球阴影与首个面板的关系，因此不采用。

### 2. 在 Theme.swift 中集中管理布局间距

新增 `LayoutSpacing` 语义命名空间，承载当前生效界面使用的外边距、主层级间距、面板内边距、紧凑间距、行内间距和工作态额外缓冲。迁移 `MenuBarView`、`IdleView`、`CleaningView`、`CandidateReviewSection` 和 `CandidateRowView` 的 `padding` 与 Stack `spacing`，尺寸和状态相关的 `frame` 值保持原样。

不把所有值强行压成同一个 4pt 网格。文本基线、候选锚点和面板标题等已有特殊值保留独立语义，避免为了形式统一破坏当前紧凑布局。

### 3. 删除未挂载的完成态视图

先确认整个源码和项目配置没有 `CompletedView` 引用，再删除 `src/Views/Screens/CompletedView.swift`。当前完成态由 `MenuBarView` 直接使用 `CleaningView`，因此无需迁移调用方或保留兼容包装。

### 4. 区分空结果与部分扫描结果

在 `ProviderStatusRow` 中，partial 且候选数为 0 时使用绿色勾号，与 completed 的空结果保持一致；partial 且存在候选项时继续使用警示三角形。这样 0 项不会被表达为异常，同时仍保留需要用户复核的部分结果提示。

### 5. 仅在扫描阶段启用呼吸效果

将 `PrimaryActionCircle` 的动画输入命名为 `isBreathing`，由 `CleaningView` 仅在 `.scanning` 状态传入 true。组件内部拆分为扫描呼吸分支和静态分支，只有扫描分支创建 `repeatForever` 动画；扫描结束后移除该分支，避免循环动画残留。`.applying`、完成、部分完成和空闲状态只保留静态圆球与必要的悬停反馈。

### 6. 过滤无释放价值的项目产物

在 `appendExisting` 中先解析候选大小，只有结果明确为 `0` 时跳过候选项。`nil` 仍传递给候选模型并显示大小未知，避免把大小未知误判为空内容。这样应用残留、项目产物和常规清理共用一致的过滤规则。

### 7. 同时展示已选和总大小

`CleanerViewModel` 分别计算当前已选候选项大小和候选列表中所有已知大小的总和。标题沿用现有数量统计，在大小区域显示为“已选大小 / 总大小”；大小未知的候选项不计入总和。

### 8. 扩大候选项点击区域

`CandidateRowView` 仅使用名称 `Button` 触发既有的 `toggle` 操作，左侧选择图标继续保留独立按钮，避免扩大点击范围。通过 `isEnabled` 保持不可选候选不可点击，并继续保留候选行的排除上下文菜单。

### 9. 保持清理操作按钮可见

`CleaningView` 在 `.applying` 状态继续挂载 `CleanupReviewActions`。其中“移到废纸篓”按钮保持可见但由 `viewModel.isCleaning` 禁用；“完成”按钮仅在等待确认或清理结束后显示，避免清理过程中触发 `resetToIdle()`。圆球标题沿用状态映射，`.applying` 显示“正在清理”，`.completed` 或 `.partial` 显示“清理完成”。

## Risks / Trade-offs

- **工作态面板整体高度增加 8pt** → 保持候选列表和其他 section 间距不变，并通过 Debug App 观察扫描和确认状态的弹出窗口高度。
- **集中常量可能掩盖特殊的光学微调** → 使用语义名称区分通用间距和锚点、基线等特殊值，不做机械替换。
- **删除旧视图可能遗漏隐式引用** → 删除前使用全仓库 `rg` 检查，并以 Debug 构建作为最终验证。
- **部分扫描但 0 项可能隐藏扫描不完整** → 仅调整状态行的视觉表达，不改变 provider outcome、诊断信息或权限提示；有候选项的 partial 状态仍显示警示图标。
- **扫描结束后仍可能残留循环动画** → 将呼吸动画放在只在 `.scanning` 存在的独立子视图中，扫描结束时移除该子视图，不让常驻圆球继续持有 `repeatForever`。
- **0 字节内容从不同 provider 入口进入候选列表** → 在 `appendExisting` 统一过滤明确的 0 字节结果，不改变大小未知候选项的展示。

## Migration Plan

1. 完成布局常量迁移、工作态缓冲和旧视图删除。
2. 执行 Debug 构建，关闭旧 CleanMac 实例并启动最新构建。
3. 检查空闲、扫描和扫描完成/确认状态，确认圆球顶部位置与候选布局未发生非预期变化。

无需数据迁移；如需回滚，只需恢复本 change 的源文件和删除的旧视图文件。
