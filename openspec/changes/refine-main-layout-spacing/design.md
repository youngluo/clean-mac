## Context

当前主界面由 `MenuBarView`、`IdleView`、`CleaningView` 和候选项组件共同组成。顶部定位使用 `22pt`，工作态内容区使用 `14pt`，圆球工作态还会放大并增加阴影，因此圆球下方需要额外的布局缓冲。多个视图各自直接写入间距数字，且 `CompletedView` 已没有调用方。provider 状态行还会把所有 partial 结果显示为警示图标，即使候选数为 0，也会让空结果看起来像异常。

## Goals / Non-Goals

**Goals:**

- 只增加工作态圆球下方的布局缓冲，不改变圆球顶部定位。
- 用集中、语义化的间距常量替代当前生效视图中的重复间距字面量，保留现有信息密度。
- 删除确认没有引用的旧完成态视图。
- 让 0 项的 provider 状态显示为正常完成态，同时保留有候选项的 partial 状态提示。
- 将圆球呼吸效果限制在扫描阶段，避免清理执行或结果状态继续产生动态干扰。
- 让主题色收敛为 `#3FA796`，用 `#E8D9B5` 做低频辅助强调，并仅保留失败色作为独立负向状态。
- 让主弹出层和三个内容面板使用稳定的主题表面色，系统材质只承担轻微质感。
- 移除主界面顶部的应用名称文字，仅保留启动磁盘信息作为顶部上下文。
- 圆形主操作继续使用深青黑作为边缘描边，但圆球内部文字和主操作按钮文字统一使用白色，避免两个主操作出现不同的前景色。
- 浅色主题使用冷中性浅灰绿作为统一面板表面，避免近白面板在浅色背景上显得发灰或漂浮；深色主题同步保留同一层级关系。
- 避免桌面背景通过透明层改变应用整体色相。
- 在统一候选入口过滤实际测得为 0 KB 的可清理候选项，避免展示无法释放空间的空文件或空目录；大小未知的候选项继续保留。
- 在候选列表标题中保留已选大小，并追加全部候选项的已知大小总和，使用 `/` 分隔，避免用户只能看到当前选择而无法估算全部可清理空间。
- 仅将候选项名称作为选择按钮，路径、大小和行内空白不触发选择；已完成、受保护或其他不可选候选保持禁用。
- 清理执行状态继续渲染底部操作区，保留“移到废纸篓”按钮并依赖 `isCleaning` 禁用重复点击；“完成”按钮也始终保留，但在清理执行期间禁用，避免触发 `resetToIdle()`。

**Non-Goals:**

- 不调整候选分组间距、候选列表高度或扫描说明收起逻辑。
- 不改变清理行为、候选排序、状态机、圆球尺寸或动画参数；颜色集中在共享主题定义中，材质调整仅影响视觉层。
- 不引入新的依赖，也不修改持久化数据。

## Decisions

### 1. 仅在工作态圆球下方增加缓冲

在 `CleaningView` 中只给 `PrimaryActionCircle` 增加底部布局缓冲，使用 `8pt`，保留根 `VStack` 的现有 `14pt` 分段间距。这样圆球顶部和中心位置不变，provider 面板、候选列表以及操作按钮之间的间距也不会被一并放大。

备选方案是修改整个 `CleaningView` 的 `VStack` 间距，但这会同时扩大所有内容区间距，无法精确解决圆球阴影与首个面板的关系，因此不采用。

### 2. 在 Theme.swift 中集中管理布局间距

新增 `LayoutSpacing` 语义命名空间，承载当前生效界面使用的外边距、主层级间距、面板内边距、紧凑间距、行内间距和工作态额外缓冲。迁移 `MenuBarView`、`IdleView`、`CleaningView`、`CandidateReviewSection` 和 `CandidateRowView` 的 `padding` 与 Stack `spacing`，尺寸和状态相关的 `frame` 值保持原样。

不把所有值强行压成同一个 4pt 网格。文本基线、候选锚点和面板标题等已有特殊值保留独立语义，避免为了形式统一破坏当前紧凑布局。

### 3. 删除未挂载的完成态视图

先确认整个源码和项目配置没有 `CompletedView` 引用，再删除 `src/Views/Screens/CompletedView.swift`。当前完成态由 `MenuBarView` 直接使用 `CleaningView`，因此无需迁移调用方或保留兼容包装。

### 4. 区分空结果与部分扫描结果

在 `ProviderStatusRow` 中，partial 且候选数为 0 时使用绿色勾号，与 completed 的空结果保持一致；partial 且存在候选项时继续使用警示三角形。这样 0 项不会被表达为异常，同时仍保留需要用户复核的部分结果提示。

### 5. 仅在扫描阶段启用呼吸效果

将 `PrimaryActionCircle` 的动画输入命名为 `isBreathing`，由 `CleaningView` 仅在 `.scanning` 状态传入 true。组件内部拆分为扫描呼吸分支和静态分支，只有扫描分支创建 `repeatForever` 动画；扫描结束后移除该分支，避免循环动画残留。`.applying`、完成、部分完成和空闲状态只保留静态圆球与必要的悬停反馈。

### 6. 过滤无释放价值的项目产物

在 `appendExisting` 中先解析候选大小，只有结果明确为 `0` 时跳过候选项。`nil` 仍传递给候选模型并显示大小未知，避免把大小未知误判为空内容。这样应用残留、项目产物和常规清理共用一致的过滤规则。

### 7. 同时展示已选和总大小

`CleanerViewModel` 分别计算当前已选候选项大小和候选列表中所有已知大小的总和。标题沿用现有数量统计，在大小区域显示为“已选大小 / 总大小”；大小未知的候选项不计入总和。

### 8. 扩大候选项点击区域

`CandidateRowView` 仅使用名称 `Button` 触发既有的 `toggle` 操作，左侧选择图标继续保留独立按钮，避免扩大点击范围。通过 `isEnabled` 保持不可选候选不可点击，并继续保留候选行的排除上下文菜单。

### 9. 保持清理操作按钮可见

`CleaningView` 在 `.applying` 状态继续挂载 `CleanupReviewActions`。其中“移到废纸篓”按钮保持可见但由 `viewModel.isCleaning` 禁用；“完成”按钮仅在等待确认或清理结束后显示，避免清理过程中触发 `resetToIdle()`。圆球标题沿用状态映射，`.applying` 显示“正在清理”，`.completed` 或 `.partial` 显示“清理完成”。

### 10. 让图标主导主题色，保留系统材质底色

应用使用 `#3FA796` 作为唯一主色，主操作、选中、扫描中和成功状态保持同一色系。`#E8D9B5` 只用于低频背景或细节强调，取消、受保护说明和低风险 partial 使用系统次要文本色，失败使用低饱和暖砖红。

面板背景使用稳定的动态主题表面色，边框和正文继续使用系统颜色。辅助色不扩展为大面积背景，菜单栏图标继续保持 template rendering，由 macOS 根据状态栏环境决定单色显示，不额外染色。

### 11. 成功结果仅保留图标

候选项完成清理后已经通过左侧成功图标表达结果，隐藏 `.movedToTrash` 和 `.removed` 的结果文案，避免路径下方重复出现“已移到废纸篓”或“已清理”。失败、跳过和取消仍保留文字结果，失败优先展示 provider 返回的具体消息。

### 12. 将主清理操作固定在操作区左侧

`CleanupReviewActions` 使用固定的从左到右顺序渲染“移到废纸篓”、重新扫描和完成/取消。重新扫描按条件显示，但不会占据主操作之前的位置，确保用户在不同状态下都能快速定位主要操作。

### 13. 提高毛玻璃凝实度

主弹出层和三个内容面板使用动态主题背景和面板色，系统 `thinMaterial` 只作为轻微质感叠加。这样既保留原生材质的触感，又避免透明层让桌面背景参与主要配色。

### 14. 使用中性底色稳定毛玻璃颜色

主弹出层由 AppKit 的原生 Popover 材质承接，三个内容面板共用稳定的动态主题面板色。品牌青绿色只用于主操作和正向状态，辅助色只承担低频细节，不让桌面壁纸的色彩污染内部面板。

### 15. 统一 NSPopover 外层背景

`NSPopover` 的箭头、外壳和根内容背景均由 AppKit 承担。`MenuBarView` 不绘制不透明根背景，只保持透明，让尖角与内容区始终来自同一套原生 Popover 材质；主题面板色只用于内部信息面板。

### 16. 用系统色表达四种语义状态

选中、成功和正在扫描状态统一使用品牌青绿色 `#3FA796`，形成单一主色闭环。取消、受保护说明和低风险 partial 状态使用系统次要文本色，失败使用低饱和暖砖红 `#A65C58`。辅助色 `#E8D9B5` 只作为低频背景或细节强调，不承担正文或状态文字。

### 17. 保持清理视图的稳定身份

`CleanupHomeView` 将扫描、等待确认、清理中、完成和部分完成状态统一渲染为同一个 `CleaningView` 分支，避免状态从 `.applying` 切换到 `.completed` 或 `.partial` 时发生结构性重挂载。候选项继续使用稳定的候选 ID，清理完成只更新行内结果状态，从而保留候选列表的当前滚动位置。

### 18. 统一主操作的品牌色

圆形主操作和“移到废纸篓”按钮统一使用品牌青绿色 `#3FA796`，前景使用深青黑 `#0B2B26`。该组合在小字号操作文字上保持足够对比度；重新扫描、完成和取消继续使用中性次要按钮样式。

### 19. 同步 Popover 外壳与内容外观

`NSPopover` 的 `appearance`、`NSHostingController.view.appearance` 和内容窗口外观统一取 `NSApp.effectiveAppearance`。SwiftUI 根视图保持透明，由 AppKit 的原生 Popover 背景承接尖角和根内容区；这样浅色、深色和手动切换主题时不会出现两套根背景。

### 20. 让 Popover 原生材质承接根背景

SwiftUI 根视图保持透明，三个内容面板使用同一套动态面板色，系统材质只作为内部面板的轻微质感叠加。这样 AppKit 统一承接根背景和尖角，内部面板仍能保持稳定的主题层级；外观同步仍由 `NSPopover`、HostingView 和内容窗口共同维护。

### 21. 用中性信息层级表达权限提示

完全磁盘访问提示属于需要处理的系统信息，不直接使用警告色填充整块提示。使用 `lock.shield` 表达系统权限保护，图标和“去设置”均使用品牌青绿色，保持主色一致；设置入口只保留文字操作，不额外显示右侧的重新检查图标；候选 partial、取消和受保护说明使用系统次要文本色，只有真正失败才使用暖砖红。

### 22. 统一三个内容面板的轻量毛玻璃

权限提示、扫描进度和可清理项目三个内容面板统一使用同一个动态面板色，避免同一应用中出现不同表面层级。系统 `thinMaterial` 只作为轻微质感叠加，底层使用近不透明的主题面板色，不让桌面背景决定最终颜色；保留 0.5pt 的低对比度描边，面板圆角和布局间距继续保留各自的既有设置。

### 23. 移除主界面的重复品牌标识

`CleanupHomeView` 顶部仅保留启动磁盘图标和可用空间信息，移除 `CleanMac` 文字标题。菜单栏图标仍作为应用入口和系统状态栏标识保留，不改变应用名称、菜单栏行为或本地化内容。

### 24. 提高圆球内文字对比度

`PrimaryActionCircleBase` 的圆球背景继续使用品牌色 `#3FA796`，内部操作文字和“移到废纸篓”按钮文字都使用白色。其他次要按钮继续使用中性前景，不改变按钮层级。

### 25. 收敛面板表面层级

根背景不再设置自定义颜色，由 `NSPopover` 原生材质统一绘制尖角和内容外壳；浅色主题的内部面板使用 `#E9EFED`，深色主题使用 `#223631`。面板继续保留 `thinMaterial` 和低对比度描边，避免面板与原生外壳之间出现第二套根背景。

## Risks / Trade-offs

- **工作态面板整体高度增加 8pt** → 保持候选列表和其他 section 间距不变，并通过 Debug App 观察扫描和确认状态的弹出窗口高度。
- **集中常量可能掩盖特殊的光学微调** → 使用语义名称区分通用间距和锚点、基线等特殊值，不做机械替换。
- **删除旧视图可能遗漏隐式引用** → 删除前使用全仓库 `rg` 检查，并以 Debug 构建作为最终验证。
- **部分扫描但 0 项可能隐藏扫描不完整** → 仅调整状态行的视觉表达，不改变 provider outcome、诊断信息或权限提示；有候选项的 partial 状态仍显示警示图标。
- **扫描结束后仍可能残留循环动画** → 将呼吸动画放在只在 `.scanning` 存在的独立子视图中，扫描结束时移除该子视图，不让常驻圆球继续持有 `repeatForever`。
- **0 字节内容从不同 provider 入口进入候选列表** → 在 `appendExisting` 统一过滤明确的 0 字节结果，不改变大小未知候选项的展示。
- **品牌色与浅色前景在小字号下对比不足** → 主操作保留 `#3FA796`，改用深青黑 `#0B2B26` 前景；面板与正文使用明暗模式对应的稳定主题表面色。
- **成功状态缺少文字后可能降低可理解性** → 保留成功图标并使用既有状态汇总信息，只有候选行内的重复成功文案被隐藏。
- **稳定表面色可能削弱层次感** → 保留 `thinMaterial` 和低对比度描边作为轻微质感，通过 Debug App 检查主弹出层和三个内容面板在明暗模式下的层次。
- **不透明面板可能削弱毛玻璃质感** → 保留 `thinMaterial` 作为轻微叠加，并使用低对比度描边维持材质边缘，但不允许桌面背景参与主要配色。
- **移除根视图毛玻璃可能降低整体通透感** → 只移除与 AppKit popover 外壳冲突的根层材质，provider 面板和其他内容卡片继续使用 `regularMaterial`。
- **统一降低面板材质强度可能降低可读性** → 保留 `thinMaterial`、低对比度描边以及系统主次文字颜色，并通过 Debug App 检查权限提示、扫描进度和可清理项目三个面板的文字对比度。
- **移除顶部标题可能削弱应用识别** → 保留菜单栏图标、磁盘信息和现有主操作，不改变应用名称或系统入口。
- **圆球文字与按钮文字的前景不一致** → 圆球和“移到废纸篓”共用白色，其他次要按钮继续使用中性前景，避免主操作之间出现视觉分裂。
- **面板对比度过低会让内容分组不清晰** → 浅色主题使用略深于根背景的冷中性面板色，深色主题保持对应的深色层级，并继续用材质与描边提供边界。

## Migration Plan

1. 完成布局常量迁移、工作态缓冲和旧视图删除。
2. 执行 Debug 构建，关闭旧 CleanMac 实例并启动最新构建。
3. 检查空闲、扫描和扫描完成/确认状态，确认圆球顶部位置与候选布局未发生非预期变化。

无需数据迁移；如需回滚，只需恢复本 change 的源文件和删除的旧视图文件。
