# cleanmac-app 规范

## Purpose

CleanMac 提供一条聚焦的菜单栏清理流程，用于检查启动磁盘并展示需要用户确认的清理候选项，不暴露多个相互竞争的入口。
## Requirements
### Requirement: 统一清理扫描范围

应用 SHALL 从一键清理主操作启动一次统一扫描，覆盖深度清理、应用清单及残留、缓存与服务刷新机会、项目产物，以及合并后的空间分析（安装包、压缩包、指定目录中的大文件和 Time Machine 状态）。

#### Scenario: 完成一键扫描

- **WHEN** 用户启动一键清理
- **THEN** 应用检查统一扫描中的每个启用 provider
- **AND** 报告每个 provider 已完成、已跳过、部分完成或失败
- **AND** 不要求用户单独进入空间分析入口

#### Scenario: 安全候选项和复核候选项

- **WHEN** 统一扫描发现候选项
- **THEN** 明确安全的候选项可以默认选中，但不会执行
- **AND** 应用、应用残留、项目依赖和大文件扫描候选项保持待复核状态

### Requirement: 统一清理扫描性能

统一清理 SHALL 在保证缓存、项目产物、应用残留和空间分析覆盖范围的前提下，尽量复用同一次目录和文件属性读取。目录候选 SHALL 在一次聚合遍历中同时得到实际分配空间、逻辑大小和扫描完整性；空间分析 SHALL 复用已经完整扫描的目录，不得因复用而遗漏适用的安装包、压缩包或普通大文件规则。

#### Scenario: 目录聚合一次完成

- **WHEN** provider 计算目录候选的体积
- **THEN** 一次遍历同时计算实际分配空间和逻辑文件大小
- **AND** 候选展示和清理汇总使用实际分配空间
- **AND** 清理前复核可以使用同一次聚合产生的逻辑大小快照

#### Scenario: 空间分析复用完整扫描目录

- **WHEN** 空间分析遍历到本次统一扫描中已经完整读取的缓存、项目产物或残留目录
- **THEN** 应用复用该目录的聚合统计并跳过重复递归
- **AND** 将复用的实际分配空间合并到启动磁盘统计
- **AND** 首次遍历中适用的空间分析候选观察项仍然进入统一候选集合

#### Scenario: 不完整目录继续补扫

- **WHEN** 已有 provider 因取消、超时、权限错误、读取失败或入口限制未完整读取目录
- **THEN** 应用不得将该目录标记为可复用边界
- **AND** 空间分析继续尝试读取该目录并保留部分完成或不可用诊断

#### Scenario: 父目录候选保持唯一归属

- **WHEN** 已完整扫描的父目录已经作为缓存、项目产物或残留候选覆盖其子树
- **THEN** 空间分析不再为同一子树创建重复文件候选
- **AND** 父目录的实际占用空间只计入一次
- **AND** 未被父目录候选覆盖的相邻目录继续参与全局空间分析

#### Scenario: 未归属目录保持全局发现

- **WHEN** 文件位于未被其他 provider 完整扫描的允许用户目录
- **THEN** 空间分析继续识别全局安装包和压缩包
- **AND** 继续识别 `~/Downloads`、`~/Desktop`、`~/Documents` 中逻辑大小超过 10 MB 的普通文件

#### Scenario: 缓存扫描不承担无效观察开销

- **WHEN** provider 聚合位于 `Library` 下的缓存或应用残留目录
- **THEN** provider 只读取创建目录候选所需的实际占用、逻辑大小和文件身份信息
- **AND** 不收集空间分析观察项或读取观察项专用的修改时间
- **AND** 项目产物等允许空间分析的目录继续收集安装包、压缩包和普通大文件观察项

#### Scenario: 临时文件扫描不执行外部占用检查

- **WHEN** 缓存清理扫描临时目录中的候选文件
- **THEN** 应用不得启动 `lsof` 或其它逐文件占用检查进程
- **AND** 应用依据文件类型、修改时间、所有者和符号链接状态筛选候选
- **AND** 临时文件只有在超过 15 天未修改时才进入候选
- **AND** 清理前重新校验文件身份、实际大小和逻辑大小，内容发生变化时跳过

#### Scenario: 当前用户临时文件使用系统废纸篓

- **WHEN** 缓存清理发现当前用户拥有的临时文件
- **THEN** 应用通过系统废纸篓 API 移动文件，不为该文件启动管理员特权命令
- **AND** 只有真正需要系统权限的缓存、日志或 Time Machine 操作才使用清理会话的管理员授权

### Requirement: 单界面清理交互

应用 SHALL 在同一个主弹出面板中呈现空闲、扫描中、等待确认、清理中和结果状态。状态变化 SHALL 更新当前界面内容，不应跳转到独立的清理、分析或完成页面。

#### Scenario: 统一进度界面

- **WHEN** 用户启动统一扫描或清理
- **THEN** 同一界面显示当前阶段、进度和取消控制
- **AND** 只使用一个主要阶段提示，不额外叠加 loading
- **AND** 圆形主按钮与 provider 进度面板之间不显示额外的阶段辅助行，扫描和清理状态由圆形按钮及 provider 区域表达

#### Scenario: 圆形主操作反馈

- **WHEN** 用户将鼠标移到“一键清理”圆形按钮上或按下按钮
- **THEN** 按钮使用 macOS 系统蓝，仅显示白色阶段文案、短暂的白色边缘和轻微的抬升、回弹反馈
- **AND** 用户启动扫描后，圆形按钮通过整体轻微呼吸、抬升和倾斜表达当前工作状态，不额外显示 loading
- **AND** 扫描阶段日志中处于“扫描中”的 provider 使用循环箭头图标并持续旋转，进入清理阶段后停止旋转
- **AND** 开启减少动态效果时不显示悬停环和微动

#### Scenario: 检查完成仍留在主界面

- **WHEN** 统一扫描完成并进入等待确认
- **THEN** 同一主界面的圆形按钮显示“扫描完成”文案，不显示图标
- **AND** 圆形按钮停止呼吸、抬升和倾斜动效
- **AND** provider 日志位于圆形按钮下方，候选结果和确认操作位于日志下方
- **AND** 圆形主按钮与 provider 日志之间不显示额外的阶段辅助行
- **AND** provider 分类列表在扫描完成后显示“已扫描完成”标题
- **AND** provider 和可清理项目分组统一使用“缓存清理”“项目清理”“应用残留”“空间分析”名称
- **AND** 仅扫描中的 provider 在名称下显示一行仅含对应扫描范围的说明文案，扫描完成后通过短动画收拢隐藏说明占用的间距，减少动态效果设置下直接收拢
- **AND** 有对应候选分组的 provider 行可点击，并将候选列表滚动到同名分组标题；没有对应候选分组的 provider 行不可点击
- **AND** 扫描完成后的 provider 行和候选分组使用紧凑的垂直间距，状态切换不发生瞬间跳变
- **AND** provider 日志在有可测量数据时显示对应候选体积
- **AND** 大文件扫描有候选但没有可测量体积时显示“大小未知”

#### Scenario: 等待确认

- **WHEN** 只读扫描完成
- **THEN** 同一界面保留所有可处理候选项
- **AND** 选择变化不会把候选项从列表中移除
- **AND** 每个候选项展示单行路径，过长路径使用末尾省略，悬停可查看完整路径
- **AND** 候选区标题展示“可清理项目”、已选数量和已选项目的总大小
- **AND** 每个候选项上侧展示名称和可测量体积，下侧展示单行路径，分类汇总由分组标题承担
- **AND** 分组标题与候选区顶部内容保持一致的水平边距
- **AND** 具体项目列表的可滚动区域最小高度为 320，最大高度为 640，超出最大高度后滚动
- **AND** 候选分组之间使用紧凑留白，不绘制可见横向分隔线，provider 跳转使用稳定的分组标识定位到对应分组
- **AND** 每个 provider 锚点包含一致的顶部留白，首个“缓存清理”分组滚动后不贴近候选标题栏
- **AND** 分组默认展示和锚点滚动后的顶部留白保持一致
- **AND** 候选标题栏与具体项目列表保持清晰分隔，路径默认使用中性文字，交互时使用主题强调色
- **AND** 路径仅用于识别候选位置，不提供打开路径操作
- **AND** “移到废纸篓”和“取消”按钮在候选列表下方按内容宽度紧凑居中并列展示
- **AND** 候选项使用紧凑的圆形复选框
- **AND** 不移动或删除任何文件和目录

#### Scenario: 直接移到废纸篓

- **WHEN** 用户点击“移到废纸篓”
- **THEN** 应用开始执行清理操作
- **AND** 选中的文件和目录通过 macOS 废纸篓处理

#### Scenario: 执行前取消

- **WHEN** 用户在执行前点击“取消”
- **THEN** 应用返回候选项列表
- **AND** 不改变任何文件或目录

#### Scenario: 清理完成仍留在主界面

- **WHEN** 扫描或确认后的清理完成
- **THEN** 同一界面显示圆形按钮文案“清理完成”以及“可清理项目”列表
- **AND** 已处理候选项直接在原列表行显示“已移到废纸篓”“已清理”“失败”等状态
- **AND** 不显示独立的清理前后空间汇总、统计卡片或清理结果明细列表
- **AND** 仍未处理的候选项继续留在列表中，用户可以不离开该界面继续选择和确认

#### Scenario: 语言一致性

- **WHEN** 用户在右键菜单中选择应用语言
- **THEN** 主界面和右键菜单使用同一语言显示
- **AND** 扫描、清理或结果处理进行中不允许切换语言
- **AND** 语言切换不会改变当前清理候选项或文件系统状态
- **AND** 应用生成的扫描、诊断和清理结果消息在展示时按当前应用语言解析
- **AND** 未分类的系统或外部命令原文不被本地化层改写

### Requirement: 已卸载应用残留

应用 SHALL 只识别已卸载应用的高置信度残留，不得将已安装应用本体加入清理候选项。系统应用和无法明确归属的共享数据 SHALL 排除在可选择清理集合之外。

#### Scenario: 已卸载应用残留分组

- **WHEN** 扫描发现用户目录中的数据无法与当前已安装应用关联
- **THEN** 应用只将高置信度的残留作为复核分组展示
- **AND** 不将任何已安装应用本体加入清理候选项

#### Scenario: 不明确的应用残留

- **WHEN** 残留路径无法高置信度关联到某个应用
- **THEN** 应用将其标记为信息项或受保护项
- **AND** 不将该路径加入可选择清理集合

#### Scenario: 已安装应用后缀归一化

- **WHEN** Preferences 或 Saved Application State 中的项目名以 `.plist` 或 `.savedState` 结尾
- **THEN** 应用在比对已安装 Bundle ID 前去掉该后缀
- **AND** 与已安装应用匹配的数据不进入残留候选

### Requirement: 安装包和压缩包发现

应用 SHALL 在允许扫描的用户目录中全局发现用户拥有的安装包和压缩包，不受所在目录和固定体积阈值限制，并在用户确认删除前保持未选中。

#### Scenario: 安装包和压缩包候选项

- **WHEN** 扫描在非保护位置发现 DMG、PKG、MPKG、XIP、IPSW、ZIP、RAR、7Z、TAR、GZ、BZ2、XZ 或其他配置的安装包和压缩包
- **THEN** 应用报告其路径和可测量体积，并作为待复核候选项展示
- **AND** 在明确确认前不移除该文件

#### Scenario: 常用目录普通大文件

- **WHEN** 扫描在 `~/Downloads`、`~/Desktop` 或 `~/Documents` 发现非安装包和非压缩包的普通文件且其体积大于 10 MB（10,000,000 字节）
- **THEN** 应用将其并入“空间分析”分组并报告路径和可测量体积
- **AND** 该候选项保持待复核状态

#### Scenario: 候选体积使用实际占用空间

- **WHEN** 扫描文件或目录候选项并计算可释放体积
- **THEN** 应用优先报告文件系统实际分配的空间，而不是直接使用逻辑文件大小
- **AND** 对目录聚合体积去重硬链接文件，避免重复计入同一份已分配空间
- **AND** 清理前同时复核实际分配空间和逻辑文件大小的变化

### Requirement: 缓存和服务刷新

应用 SHALL 将缓存刷新和服务刷新表示为范围受限且名称明确的操作，并分别报告结果。一次清理不得终止无关用户进程或执行范围不受限的系统修改。

#### Scenario: 范围受限的刷新操作

- **WHEN** 存在已配置的缓存或服务刷新操作
- **THEN** 应用只在文档规定的范围内执行该操作
- **AND** 分别报告成功、跳过、失败或权限受限

#### Scenario: 不安全的刷新操作

- **WHEN** 刷新操作需要终止无关进程或改变范围不受限的系统状态
- **THEN** 应用跳过该操作
- **AND** 解释跳过原因，不将统一清理整体标记为失败

#### Scenario: 全局开发工具缓存分类

- **WHEN** 扫描发现 npm、pnpm、pip、Homebrew、Xcode 或其他已配置开发工具的全局缓存
- **THEN** 应用将其归入“缓存清理”而不是“项目清理”
- **AND** 该候选默认不选中并显示聚合体积
- **AND** 自定义缓存路径不扩大到用户目录之外

#### Scenario: 多个临时目录缓存分类

- **WHEN** 扫描发现 `/private/tmp`、`/private/var/tmp`、`/var/tmp`、`/tmp` 或当前进程临时目录下超过 15 天未修改的普通文件
- **THEN** 应用将其归入“缓存清理”而不是“空间分析”
- **AND** 该候选默认不选中，并通过系统废纸篓 API 移到用户废纸篓，不额外请求管理员权限
- **AND** 应用跳过符号链接、目录、特殊文件和非当前用户拥有的文件
- **AND** 清理前重新校验文件身份、实际大小和逻辑大小，扫描后发生变化的文件不执行清理

#### Scenario: 临时目录安全边界

- **WHEN** 扫描缓存和空间候选
- **THEN** 应用不递归扫描整个 `/private/var/folders`，只处理当前进程 `TMPDIR` 指向的具体目录
- **AND** 不自动处理近期修改的临时文件

### Requirement: 项目依赖安全

应用 SHALL 将 `node_modules` 视为项目依赖候选项，而不是通用缓存。应用 SHALL 使用修改时间、符号链接、文件身份和清理前体积复核进行安全判断，不要求 `package.json` 或 lock 文件存在，允许计算聚合体积但不展示子文件，不设置体积阈值，并且不得自动选中该候选项。

#### Scenario: 项目依赖候选

- **WHEN** 扫描器在配置的项目目录中找到 `node_modules`
- **THEN** 创建一个代表整个目录的候选项
- **AND** 可以计算该目录的聚合体积
- **AND** 不展示或列出目录内的文件

#### Scenario: 依赖保护

- **WHEN** `node_modules` 是符号链接、扫描后身份发生变化或清理前体积发生变化
- **THEN** 应用将其标记为受保护或跳过
- **AND** 不选中该候选项

#### Scenario: 项目依赖时间范围

- **WHEN** 项目产物或 `node_modules` 所在项目目录在最近 30 天内有更新
- **THEN** 应用跳过该候选项
- **AND** 超过 30 天未更新的候选项进入待复核列表

#### Scenario: 可重建项目产物

- **WHEN** 扫描在配置项目根目录中发现已识别的依赖、构建、测试或工具产物目录
- **THEN** 应用将整个目录作为默认未选中的候选并计算聚合体积
- **AND** 命中该目录后不再向内发现嵌套候选
- **AND** 全局工具缓存不进入项目清理分组

#### Scenario: 依赖候选项展示

- **WHEN** 展示扫描到的 `node_modules` 候选项
- **THEN** 只显示聚合体积和路径
- **AND** 在用户明确确认前保持未选中

#### Scenario: 依赖移除

- **WHEN** 用户确认 `node_modules` 候选项
- **THEN** 将整个目录移入 macOS 废纸篓
- **AND** 不永久删除目录内的单个依赖

### Requirement: 清理任务选择

空闲界面 SHALL 提供一个主清理操作，并在主界面状态切换时保持圆形主操作的垂直位置一致。该操作 SHALL 启动统一扫描，覆盖安全清理、已卸载应用残留、项目产物和合并后的大文件扫描。空闲界面不得再提供独立的大文件扫描或开发清理主入口。

#### Scenario: 启动统一清理

- **WHEN** 用户点击“一键清理”
- **THEN** 应用启动统一的只读扫描
- **AND** 不要求用户先选择独立的清理类别

#### Scenario: 启动磁盘访问受限

- **WHEN** macOS 尚未授予 CleanMac 完全磁盘访问权限
- **THEN** 统一扫描继续检查可读取的位置
- **AND** 同一主界面显示一条合并的权限提示，并提供前往系统设置的操作
- **AND** 权限提示使用“需要完全磁盘访问”和“开启后，扫描结果会更完整”的简短单行文案
- **AND** “去设置”操作保持统一高度和紧凑间距，不挤压提示文案
- **AND** “去设置”以纯文字操作展示，不额外显示图标
- **AND** 所有可用的界面操作在悬停时显示手形指针，禁用操作保持默认指针

#### Scenario: 空闲主操作布局

- **WHEN** 应用处于空闲状态
- **THEN** 顶部磁盘信息与圆形主操作之间有明确的垂直留白
- **AND** 圆形主操作与说明文字、权限提示之间保持舒适的垂直间距
- **AND** 圆球尺寸、主操作文案和清理行为保持不变

#### Scenario: 圆形主操作位置一致

- **WHEN** 应用在空闲、扫描、等待确认、清理中、完成或部分完成状态之间切换
- **THEN** 圆形主操作与顶部磁盘信息之间使用一致的垂直定位
- **AND** 工作状态动画不改变圆球中心位置

- **AND** 面板使用自适应中性系统底色降低桌面环境色影响，不使用固定浅蓝或灰绿色

- **WHEN** 用户查看选中、成功、警告或失败状态
- **THEN** 选中、成功和正在扫描使用 `#3FA796`
- **AND** 取消、受保护说明和低风险 partial 使用系统次要文本色
- **AND** 失败使用低饱和暖砖红
- **AND** 主操作和品牌强调使用 `#3FA796`

#### Scenario: 权限提示使用中性信息层级

- **WHEN** 用户查看完全磁盘访问权限提示
- **THEN** 权限提示使用 `lock.shield` 图标并采用 `#3FA796`
- **AND** “去设置”操作使用 `#3FA796`
- **AND** “去设置”右侧不显示重新检查图标
- **AND** 权限提示整体不使用警告色作为主要前景色
- **AND** 权限提示、扫描进度和可清理项目面板使用同一套透明材质层级
- **AND** 候选 partial、取消和受保护说明使用系统次要文本色

### Requirement: 透明毛玻璃应用背景

应用 SHALL 使用与 macOS 输入法菜单相近的透明毛玻璃背景。背景需要保留桌面环境色的柔和透出和模糊效果，不得通过固定浅蓝色或其他不透明主题色替代系统材质。参考图只约束透明材质的视觉表现，不约束应用内文字、菜单项或布局。

#### Scenario: 桌面背景能够柔和透出

- **WHEN** 用户在白色、蓝色或其他彩色桌面背景上打开主弹出面板
- **THEN** 主弹出面板能够观察到桌面环境色的变化
- **AND** 桌面图案经过毛玻璃模糊，不以清晰细节穿透面板
- **AND** 面板不会固定呈现浅蓝或浅灰绿

#### Scenario: 内容面板保持整体通透

- **WHEN** 用户查看权限提示、扫描进度或可清理项目区域
- **THEN** 内容面板使用透明系统材质或透明根背景
- **AND** 内容区域与面板边缘之间不出现明显的不透明色块断层
- **AND** 面板通过材质强度、圆角和低对比度描边维持内容层级

#### Scenario: 明暗主题同步

- **WHEN** 用户切换浅色、深色或跟随系统主题
- **THEN** 面板、HostingView、内容窗口和 SwiftUI 根视图使用同一个 effective appearance
- **AND** 透明材质自动采用对应主题的亮度与对比度
- **AND** 正文、按钮和候选项在不同桌面背景下保持可读
